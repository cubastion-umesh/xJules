Key S/4HANA Functional Impact Considerations

Mandatory Simplifications & Structural Changes from ECC6

Customer Vendor Integration (CVI)

Mandatory prerequisite prior to technical conversion. All Customers (`KNA1`) and Vendors (`LFA1`) must be converted into Business Partners (`BUT000`).


  • Must execute CVI synchronization in ECC6 before SUM DMO.
  • Number range mapping & duplicate address cleanup required.

Finance Simplification (ACDOCA)

Replacement of GL tables (COEP, FAGLFLEXA, BSIS, BSAS) with single Universal Journal table `ACDOCA`.


  • Migration to New Asset Accounting (FI-AA) mandatory.
  • Credit Management migrated to FSCM Credit Management.

Technical Considerations & Custom Code Modernization

Remediating Legacy Z-Code & Embracing Clean Core

ABAP Custom Code Remediation

  • ABAP Test Cockpit (ATC): Execute S/4HANA checks in ECC6 to identify non-compliant statements (e.g. direct table writes to COEP/BSIS).
  • HANA Database Optimization: Remove database-dependent code (Oracle specific hints) and leverage CDS Views & Open SQL.
  • Unused Code Elimination: Decommission unused Z-transactions via UPL / CCLM metrics.

Clean Core & SAP BTP Strategy

  • Decoupled Extensions: Move custom enhancements to SAP BTP (Business Technology Platform) via RAP / CAP models.
  • Standard APIs & Core Data Services: Replace direct SQL reads with standard OData services and Core Data Services (CDS).
  • UX Transformation: Transition users from SAP GUI to modern SAP Fiori Launchpad.

Data Migration & Downtime Optimization (SUM DMO)

Oracle AnyDB to S/4HANA HANA DB Migration Strategy

Database Migration Option (DMO)

SUM DMO combines Unicode Conversion, Software Upgrade, and Database Migration into a single downtime window.


  • Direct migration from Oracle AnyDB to SAP HANA DB on RISE Cloud.
  • Benchmarking table export/import performance over high-speed ExpressRoute / DirectConnect network links.

Downtime Minimization Tactics

  • DMO with Downtime Optimized Option (dt-Opt): Pre-migrates large application tables during business uptime.
  • NZDT (Near-Zero Downtime Technology): For mission-critical systems requiring < 8 hours total business outage.
  • Table Splitting & R3load Parallelization: Tuning thread count based on network bandwidth and target HANA memory.

Risk Management & Success Factors

Mitigating Critical Transformation Risks

Risk: Data Inconsistencies

Mitigation: Execute pre-conversion financial consistency checks (FIN_CORR_MONITOR) in ECC6 prior to cutover.

Risk: Interface Disruption

Mitigation: Comprehensive interface inventory; migrate legacy RFC/IDOC adapters to SAP Integration Suite (BTP) OData services.

Risk: User Resistance

Mitigation: Role-based Fiori enablement early during Explore phase; structured user adoption KPI tracking.
